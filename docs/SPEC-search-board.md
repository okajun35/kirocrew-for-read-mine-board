# Redmine Board — 検索とボードの再設計 仕様 v0.1（ドラフト）

- 位置づけ: [SPEC.md](SPEC.md) v0.3 の F-02（検索）・F-03（一覧）・F-04（カンバン）を置き換える。それ以外（接続設定、詳細、Kiro への引き渡し、MCP）は SPEC.md のまま
- 状態: **未実装・一部未検証**。`【要検証 V-xx】` は [VERIFICATION.md](VERIFICATION.md) の V-15 以降で確かめる
- 方針: Redmine の検索画面・ボードをそのまま写さない。Redmine の **クエリの力**（項目×比べ方×値、保存クエリ、ワークフロー）は使い、**操作の形**は使いやすい道具に合わせる

## 1. 背景と参考

Redmine 標準の検索は「フィルタ行を1つずつ足すフォーム」で、条件の組み立てと見直しに手間がかかる。ボードは標準に無く、プラグインが要る。次の道具の良い点を集める。

| 参考 | 種類 | 取り入れる点 |
|---|---|---|
| [Redmine expert Agile](https://www.redmine.org/plugins/redmine_expert_agile) | プラグイン | ボード＝クエリ。つかんだ時点で落とせる列を色分け。レーンに落とすとその項目が変わる。WIP 上限。カード項目の選択 |
| [チケットパネル](https://github.com/redmica/redmine_issues_panel)（ファーエンドテクノロジー） | プラグイン | 保存クエリでボードを出す。ホバーで説明。右クリックで項目変更。優先度の高いカードの強調 |
| [全文検索](https://github.com/clear-code/redmine_full_text_search)（クリアコード） | プラグイン | AND/OR/NOT の検索式。結果をメタデータでワンクリック絞り込み。類似チケット。表記ゆれ |
| [Linear](https://linear.app/docs/filters) | 外部ツール | 条件チップ。キー操作（`F`、`Cmd/Ctrl+B`）。一覧とボードで同じ条件。ビューの保存 |
| [GitHub Projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects/customizing-views-in-your-project/filtering-projects) | 外部ツール | 文字で書く検索（`field:value`、カンマで OR）。Slice by（値ごとの件数パネル）。カードの値を押して絞る。Group by とレーンへのドロップ |

全文検索プラグインの「類似チケット」「表記ゆれ」「添付ファイル内検索」は Redmine 側に Groonga と DB 拡張が要る。このアプリは REST だけなので、**似たチケットと自然文検索は Kiro（エージェント）で補う**（§9）。

## 2. 用語

| 用語 | 意味 |
|---|---|
| クエリ | 条件の集まり。内部では §3 の構造で持ち、Redmine には `issues.json` のパラメーターで送る |
| 検索式 | クエリを文字で書いたもの（§4）。人とエージェントで同じ書き方を使う |
| チップ | 検索ボックスの下に並ぶ、条件1つ分の部品 |
| ビュー | クエリ + 見え方（§7）。名前を付けて保存できる |
| 件数パネル | ある項目の値ごとの件数を出す左パネル（GitHub の Slice by に相当） |
| レーン | ボードの横の帯（swimlane）。列とは別の項目で分ける |

## 3. クエリの内部構造

```ts
type Query = {
  text: string[]          // キーワード（AND）。各語は any_searchable に渡す
  notText: string[]       // 除外キーワード
  filters: Filter[]       // 項目ごとの条件。項目どうしは AND
  sort: { field: string; dir: 'asc' | 'desc' }[]
}
type Filter = { field: FieldKey; op: Op; values: string[] }   // values は同じ項目内で OR
```

- **項目をまたぐ OR は持たない。** Redmine の IssueQuery が項目間 AND だけのため（GitHub Projects も同じ制約）【要検証 V-15】
- 同じ項目の複数値は OR（`status:進行中,フィードバック`）
- 構造は UI・backend・MCP で共通。backend が Redmine のパラメーターへ変換する（`rb_core/query.py` を新設）

### 3.1 項目

| FieldKey | 日本語の別名 | 値 | Redmine のフィルタ名 |
|---|---|---|---|
| `project` | プロジェクト | 識別子 / id | `project_id`（`subproject_id` で子を含む／除く）|
| `status` | 状態, ステータス | 名前 / id / `open` / `closed` | `status_id` |
| `tracker` | トラッカー, 種類 | 名前 / id | `tracker_id` |
| `priority` | 優先度 | 名前 / id | `priority_id` |
| `assignee` | 担当, 担当者 | `me` / `none` / ログイン名 / 名前 / id / グループ | `assigned_to_id` |
| `author` | 作成者 | 同上 | `author_id` |
| `watcher` | ウォッチ | `me` | `watcher_id` |
| `version` | バージョン | 名前 / id / `none` | `fixed_version_id` |
| `category` | カテゴリ | 名前 / id / `none` | `category_id` |
| `parent` | 親 | `#id` / `none` | `parent_id` |
| `created` / `updated` / `due` / `start` / `closed` | 作成, 更新, 期日, 開始, 完了日 | 日付・相対日付（§4.3） | `created_on` ほか |
| `done` | 進捗 | 0–100 | `done_ratio` |
| `cf.<名前>` | （カスタムフィールド名そのまま） | 型による | `cf_<id>` 【要検証 V-16】 |

名前で書かれた値は、backend がメタデータ（§8）で id に引き直す。曖昧なとき（同名の担当者が2人など）はエラーにして候補を返す。

### 3.2 比べ方（Op）と Redmine の演算子

| Op | 検索式 | Redmine `op` | 対象 |
|---|---|---|---|
| 等しい（いずれか） | `field:a,b` | `=` | 一覧型 |
| 等しくない | `-field:a` | `!` | 一覧型 |
| 値あり / 無し | `field:*` / `field:none` | `*` / `!*` | 一覧型・日付 |
| 以上 / 以下 / 範囲 | `>=` `<=` `a..b` | `>=` `<=` `><` | 日付・数値 |
| N日以内 / N日より前 | `<7d` / `>30d` | `>t-` / `<t-` | 日付 |
| 今日 / 今週 / 先週 / 今月 | `today` `this-week` `last-week` `this-month` | `t` `w` `lw` `m` | 日付 |
| 期限切れ | `due:overdue` | `<t+` + 0（相当） | 期日 |
| 含む / 含まない | 自由語 / `-語` | `~` / `!~` | `any_searchable` |

演算子の名前は Redmine のフィルタ画面で使われているもの（`>t-` など）。**REST で `f[]` / `op[]` / `v[]` の形がそのまま通るかは未確認**【要検証 V-15】。通らない演算子は §11 の段階で外す。

## 4. 検索式

### 4.1 書き方

```
担当:自分 状態:進行中,フィードバック 更新:<7d 優先度:>=高 ログイン -CSV
assignee:me status:"In Progress",Feedback updated:<7d priority:>=High login -CSV
```

- `項目:値`。値に空白があれば `"..."` で囲む
- 先頭の `-` は否定
- `項目:` の付かない語はキーワード。複数あれば AND
- 項目名・`me`/`自分`・`none`/`なし`・`today`/`今日` などは ja/en の両方を受け付ける。表示は利用者の言語に合わせる
- `#123` だけのときは今まで通りそのチケットを開く
- 優先度の `>=高` は「高以上」。優先度は Redmine の並び順（`position`）で比べ、id の集合に展開する

### 4.2 候補（オートコンプリート）

- `担` まで打つと項目名の候補、`担当:` の後は値の候補（自分、なし、メンバー）を出す
- 値の候補はメタデータ（§8）から。担当者はプロジェクトが決まっていればそのメンバー、未指定なら最近の担当者
- `↑↓` で選び、`Tab` / `Enter` で確定。確定した条件はチップになる

### 4.3 相対日付

`today`, `yesterday`, `this-week`, `last-week`, `this-month`, `last-month`, `<Nd`（N日以内）, `>Nd`（N日より前）, `YYYY-MM-DD`, `a..b`。週の始まりは Redmine の設定に従う（REST で取れないため、相対日付はできるだけ Redmine 側の演算子 `w` `lw` で送る）。

### 4.4 解析エラー

- 解析できない部分は赤い下線と、その場の説明（例「`優先:` という項目はありません。`優先度:` ですか」）
- エラーがある間も、解析できた部分だけで検索してよい（打ちながら結果が変わる）

## 5. 条件チップ

- 検索ボックスの下に、解析済みの条件を1つずつチップで並べる（`担当: 自分 ✕`）
- チップを押すと値の選択（複数選択・否定の切り替え）が開く。変えると検索式も書き換わる。**検索式とチップは常に同じものを指す**
- `✕` で外す。`+ 条件` から項目を選んで足せる（文字を打たない人向け）
- 既定の条件（`状態:未完了`）は薄く出し、外せる

## 6. 件数パネル（Slice by）

- 左に「項目を1つ選んで、その値ごとの件数」を出す。既定はステータス。担当者・トラッカー・優先度・バージョンに切り替えられる
- 件数は今のクエリにその値の条件を足して `limit=1` の `total_count` で数える。値の数だけリクエストが出るので、**上位 20 値まで**、5 分キャッシュ、ページが非表示の間は更新しない【要検証 V-18: 速さ】
- 値を押すとチップに足す。もう一度押すと外す
- 件数 0 の値は薄くする（隠さない）

## 7. ビューと見え方

### 7.1 レイアウト

- **一覧**と**ボード**は同じクエリ・同じ並び順を使う。切り替えても条件は残る（`B` キー）
- 一覧: 列の選択と並び替え、列の幅、グループ化（担当者ごとなど）、まとめて選んで一括変更（P3）
- ボード:
  - **列の項目**: ステータス（既定）/ 担当者 / バージョン / 優先度 / トラッカー
  - **レーン**: なし（既定）/ 担当者 / プロジェクト / トラッカー / 優先度 / バージョン / 親チケット
  - **カードに出す項目**: ID、トラッカー、優先度、担当者、期日、進捗、バージョン、更新日（選べる）
  - **WIP 上限**: 列ごと。超えたら列の頭を警告色にする（止めはしない。expert Agile と同じく「目安」）
  - 空の列を隠す / 出す
  - 列ごとの件数は「表示中 / 合計」。末尾に「さらに表示」

### 7.2 ドラッグ＆ドロップ

- 動かせるのは、列とレーンの項目のうち **Redmine で書き換えられるもの**（ステータス、担当者、バージョン、優先度、カテゴリ）
- つかんだ瞬間に、落とせる列とレーンを強調し、落とせないものを薄くする
  - ステータス: そのチケットの `allowed_statuses`
  - 担当者: そのプロジェクトの担当できるメンバー【要検証 V-19】
  - バージョン: そのプロジェクトで使える未完了のバージョン
- 落としたら PUT し、**必ず取り直して反映を確かめる**（Redmine は無効な変更を 204 で黙って無視する。V-02）
- 失敗したらカードを元の場所に戻し、理由を出す

### 7.3 押して絞る

- カードや行の担当者・優先度・トラッカー・バージョンを押すと、その条件をチップに足す（`Alt` 押しで否定）

### 7.4 保存ビュー

- 名前を付けて保存。保存先はアプリのデータ領域（`data/views.json`）。所有者だけが保存・削除できる
- 中身: 検索式、レイアウト、列とレーンの項目、カード項目、並び順、WIP 上限、件数パネルの項目
- 既定ビューを持つ（「自分の担当」「未割り当て」「今週更新」）
- **Redmine の保存クエリ**も一覧に出し、開ける（`/queries.json` → `issues.json?query_id=`）【要検証 V-17】。開いた後にチップで条件を足せるかは、Redmine が `query_id` と他のフィルタの併用を許すかによる。許さないときは「Redmine のクエリ」バッジを付けて条件編集を無効にする

### 7.5 キーボード

| キー | 動き |
|---|---|
| `/` | 検索ボックスへ |
| `F` | `+ 条件` を開く |
| `B` | 一覧 ⇄ ボード |
| `J` / `K` | 次 / 前のチケット |
| `Enter` | 詳細を開く |
| `Esc` | 詳細を閉じる / 入力を抜ける |
| `S` | ビューを保存 |
| `?` | キーの一覧 |

## 8. メタデータ

候補・名前の引き直し・件数パネルに使う。サーバーごとに 10 分キャッシュ（backend のメモリ）。

| 対象 | 取得元 | 備考 |
|---|---|---|
| プロジェクト | `/projects.json` | 今と同じ |
| ステータス・トラッカー・優先度 | `/issue_statuses.json`, `/trackers.json`, `/enumerations/issue_priorities.json` | |
| メンバー | `/projects/<id>/memberships.json` | 権限によって 403。そのときは最近の担当者から作る |
| バージョン・カテゴリ | `/projects/<id>/versions.json`, `/projects/<id>/issue_categories.json` | |
| カスタムフィールド | `/custom_fields.json` は**管理者だけ**。一般利用者は `/projects/<id>.json?include=issue_custom_fields` などで取る【要検証 V-16】 | 取れなければ `cf.` の候補を出さない |
| 保存クエリ | `/queries.json` | 【要検証 V-17】 |

## 9. Kiro に聞く検索（売りにする機能）

### 9.1 ことばで探す

- 検索ボックスの右の「Kiro に聞く」で、自然文を入れる（例「先週から止まっている自分のバグ」）
- アプリが同梱エージェントに頼み、**検索式を1行だけ**返してもらう。アプリはそれを §4 の解析器に通してからチップにする。**検索式として正しくなければ適用しない**（エージェントの出力も信用しない入力として扱う）
- 実行手段: `ctx.spawn`（`permissions.spawn`）でアプリのエージェントを無人で動かし、結果を待つ【要検証 V-20】。エージェントは読み取りツールだけを使う（無人実行は承認が出ないため。V-08）
- 使えないとき（spawn 不可、時間切れ 30 秒）は、チャットを開いて同じことを頼む方式に落とす

### 9.2 似たチケット

- 詳細パネルに「似たチケット」を出す。エージェントが件名と説明から語を選び、`redmine_search` で探して上位 5 件を理由つきで返す
- 開くたびには動かさない。ボタンを押したときだけ（費用と待ち時間のため）

### 9.3 MCP との揃え方

- `redmine_search` に `query`（§4 の検索式）を足す。今の個別引数（`q`, `status` ほか）は残す
- これで人とエージェントが同じ書き方で同じ結果を得られる。エージェントが作った検索式をそのまま画面のリンクにもできる

## 10. 非機能

- **リクエスト数の目安**: 一覧 1 回 = 1。ボード = 列の数（最大 12）。件数パネル = 値の数（最大 20）。同時に Redmine へ出すのは 6 本まで
- 入力中の検索は 300ms 待ってから送り、古い要求はキャンセルする
- 全項目名・演算子・エラーは ja/en を辞書で持つ。**backend のエラーも code を返し、文言は UI の辞書で出す**（今は英語の文が出ている）
- 色だけで状態を区別しない（WIP 超過、落とせない列など）

## 11. 段階

| 段階 | 中身 | 目安 |

| P1 | 検索式の解析と変換（§3・§4）、チップ（§5）、一覧とボードの条件共有、押して絞る（§7.3）、保存ビュー（自前のみ）、キーボード（§7.5）、backend エラーの code 化 | Kiroween のデモに必須 |

## 12. やらないこと

- 項目をまたぐ OR（Redmine にない）
- Wiki・ニュース・添付ファイルの中身の検索
- 表記ゆれ辞書（Kiro に聞く検索で代わりにする）
- スコア順の並び（REST に関連度が無い）
- Redmine 側のプラグイン・Webhook
